## 1. Instância de `Monoid` para `Sozinho`

Dado:

```haskell
data Sozinho = Sozinho
```

Esse tipo só tem **um único valor possível**, então ele é um caso clássico de monóide trivial.

```haskell
instance Semigroup Sozinho where
    Sozinho <> Sozinho = Sozinho

instance Monoid Sozinho where
    mempty = Sozinho
```

✅ Justificativa:

* Só existe um valor → qualquer combinação resulta nele mesmo.
* `mempty` precisa ser o elemento neutro → só pode ser `Sozinho`.

## 2. O tipo `String` com operação `ign`

Dada:

```haskell
ign :: String -> String -> String
ign l m = m
```

Essa operação **ignora o primeiro argumento** e sempre retorna o segundo.

Queremos saber se (`String`, `ign`, `[]`) forma um monóide.

---

### ✔ Verificando as propriedades

### (1) Associatividade

Precisamos verificar:

```haskell
ign x (ign y z) == ign (ign x y) z
```

Calculando:

* Lado esquerdo:

```haskell
ign x (ign y z) = ign x z = z
```

* Lado direito:

```haskell
ign (ign x y) z = ign y z = z
```

✅ Associativa ✔

---

### (2) Elemento neutro

Para ser monóide, `[]` deve satisfazer:

#### Neutro à esquerda:

```haskell
ign [] x = x   ✔
```

#### Neutro à direita:

```haskell
ign x [] = []  ✘ (deveria ser x)
```

❌ Falha aqui!

---

## ❌ Conclusão

**Não forma um monóide**, porque:

* A operação é associativa ✔
* Mas `[]` **não é elemento neutro à direita** ❌

Logo, não satisfaz a definição de monóide.

## ✔ Exemplo parecido que É monóide

Considere a operação:

```haskell
op :: String -> String -> String
op l m = l
```

Essa operação **ignora o segundo argumento** (ao contrário da anterior).

---

### ✔ Verificando as propriedades

### 1. Associatividade

```haskell
op x (op y z) = op x y = x
op (op x y) z = op x z = x
```

✅ Associativa ✔

---

### 2. Existe elemento neutro?

Queremos um elemento `e` tal que:

```haskell
op e x = x   (neutro à esquerda)
op x e = x   (neutro à direita)
```

Mas:

* `op e x = e` ❌ (nunca dá `x`)
* `op x e = x` ✔

❌ Não existe elemento neutro

---

## ❌ Conclusão importante

Essa operação também **não forma um monóide**.

---

## ✔ Agora um exemplo correto (clássico)

O monóide válido com `String` é a **concatenação**:

```haskell
(<>) :: String -> String -> String
(<>) = (++)
```

Com:

```haskell
mempty = ""
```

---

### ✔ Propriedades

* Associativa:

```haskell
(x ++ y) ++ z = x ++ (y ++ z)
```

* Elemento neutro:

```haskell
"" ++ x = x
x ++ "" = x
```

## ✔ Outro exemplo interessante (bem próximo da ideia original)

Podemos usar o tipo `First`:

```haskell
import Data.Monoid

First "a" <> First "b" = First "a"
```

Ou `Last`:

```haskell
Last "a" <> Last "b" = Last "b"
```

Esses **funcionam como monóides** porque usam `Maybe` internamente para garantir um elemento neutro (`Nothing`).

## 🔎 Insight chave

Operações como:

* `ign l m = m` (pega o último)
* `op l m = l` (pega o primeiro)

**não são monóides sozinhas**, porque:
➡ não possuem elemento neutro válido

Mas podem virar monóides quando encapsuladas em tipos como:

* `Maybe`
* `First`
* `Last`

Perfeito — vamos construir o `First` **do zero**, como costuma cair em prova 👇

## ✔ Ideia

Queremos um tipo que:

* Guarde **o primeiro valor válido**
* Tenha um **elemento neutro**

O problema antes era: não existia neutro.
A solução: usar `Maybe`.

---

## ✔ Definição do tipo

```haskell id="p2g6b6"
data First a = First (Maybe a)
  deriving (Show, Eq)
```

---

## ✔ Instância de `Semigroup`

Regra:

* Se o primeiro tiver valor (`Just`), ele vence
* Senão, pega o segundo

```haskell id="1h9zzp"
instance Semigroup (First a) where
    First (Just x) <> _ = First (Just x)
    First Nothing  <> r = r
```

---

## ✔ Instância de `Monoid`

```haskell id="d7p5s8"
instance Monoid (First a) where
    mempty = First Nothing
```

---

## ✔ Exemplos de uso

```haskell id="ht7xjt"
First (Just "A") <> First (Just "B")
-- Resultado: First (Just "A")

First Nothing <> First (Just "B")
-- Resultado: First (Just "B")

First Nothing <> First Nothing
-- Resultado: First Nothing
```

---

## ✔ Por que isso agora é um monóide?

### 1. Associatividade

Herda da estrutura do `Maybe` + regra definida → ✔

---

### 2. Elemento neutro

```haskell id="7d62gn"
mempty = First Nothing
```

Verificando:

```haskell id="iv4uzk"
First Nothing <> x = x
x <> First Nothing = x
```

✔ Funciona dos dois lados

---

## ✔ Intuição

* `First` = "pega o primeiro valor disponível"
* `Nothing` = "não tem valor ainda" → neutro perfeito

---

## ✔ Versão dual: `Last`

Só inverter a lógica:

```haskell id="g3k1ny"
data Last a = Last (Maybe a)
  deriving (Show, Eq)

instance Semigroup (Last a) where
    _ <> Last (Just y) = Last (Just y)
    l <> Last Nothing  = l

instance Monoid (Last a) where
    mempty = Last Nothing
```

---

## 🧠 Resumo que cai em prova

* Operações como “pegar primeiro” ou “pegar último” **não são monóides sozinhas**
* Precisam de um **contexto com neutro**, como `Maybe`
* `Nothing` funciona como identidade
